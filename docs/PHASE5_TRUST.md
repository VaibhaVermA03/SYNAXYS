# Phase 5: favicon, licence, security policy, Privacy Policy and Terms

Status: implemented; the legal texts are **drafts with placeholders** that need your information and a lawyer's review before publication. Nothing was invented: no company name, address, e-mail, phone, URL, jurisdiction or model-provider terms. Everything only you can supply is a highlighted `[[placeholder]]`; the full checklist is `docs/legal/PLACEHOLDERS.md`.

## What the Privacy Policy states, and where it comes from in the code
* **Code goes to OpenAI** (diff text of eligible changed files, PR title and branch names, workspace rules, retrieved code excerpts up to 4,000 characters; code chunks and search queries for embeddings) and **to Pinecone** (vectors plus metadata with up to 1,500 characters of text per chunk, one namespace per repository). Prominent notice in section 2 and 5/6. No claim that code is never shared, that embeddings cannot contain sensitive information, or about OpenAI's retention: that is left as a placeholder tied to your agreement with OpenAI.
* Stored personal data (GitHub id, login, name, public e-mail, avatar, encrypted token, session hash + user agent), workspace data, review results (which quote code), audit and job records, cookies/local storage, Sentry and Redis, the retention periods (checked against the default settings by a test), export and deletion behaviour, GitHub App permissions and webhook events.
* Hosting providers, regions, models in use, legal bases, transfers, controller/processor roles, backups and contacts are placeholders.

## Behaviour fixed while writing the policy
Deleting a workspace (or the account of its only member) used to detach its repositories but leave their pull requests, reviews, findings and comments in the database. It now **purges** them (`workspace_service.purge_repositories`, explicit deletes in dependency order, queued reviews/jobs for them cancelled, vectors removed by an `index_delete` job with `purged: true`). The UI texts and `docs/PHASE4_WORKSPACES.md` were updated. This is covered by `test_phase16_db.py` (NOT RUN).

## What you must do
1. Fill the placeholders (`docs/legal/PLACEHOLDERS.md`) in `frontend/src/legal/*.json`, `LICENSE` and the top of `SECURITY.md`; run `python backend/tools/gen_legal_docs.py`.
2. Have a lawyer review all four documents, then remove the draft banner by setting `"kind"`/`"banner"` accordingly (the banner is part of the JSON).
3. Publish `/.well-known/security.txt` only with real values (`docs/security.txt.template`); a security.txt with placeholders must not be served.
4. List third-party licences before distributing the software (for example generated from `package-lock.json` and the Python requirements; the Geist Pixel font is under the SIL OFL 1.1).
5. Verify the CSP in the browser (Report-Only) with the favicon and manifest: both are same-origin and covered by `img-src 'self'` / `manifest-src 'self'`.
6. Check the favicon in a real browser (tab, dark mode, iOS home screen); only the files themselves were inspected.

## Limits
* The documents describe what the software does; they are not legal advice, a certification, or a DPA.
* The privacy text will go out of date when features change: re-read it whenever data flows change (the test only checks retention defaults and key facts).
* No cookie banner is included because only a strictly necessary session cookie and non-personal local-storage entries are used; confirm that with counsel for your jurisdictions.
